title: Files, saving and sharing
summary: Where your designs live, how to back them up, which formats layerling imports and exports, and what is possible on a shared server.
---

## Where your designs live

layerling saves everything in the browser on your computer. There is no account and nothing is uploaded. (With a copy you host yourself, designs can live in a shared folder on the server instead; see the section on the shared folder further down.) Every change saves itself. The preview picture on the start page shows the view you last had in front of you when you went back with {{ui:editor.homeDashboard}}. If you open layerling in the same browser days later, everything is there.

If you go back to the start page from a design with nothing in it, layerling asks whether to keep it. {{ui:confirm.yes}} or [[Enter]] keeps it, {{ui:confirm.no}} removes it, so empty designs do not pile up. For a design in a shared folder on a server, {{ui:confirm.no}} deletes the file from the server, for everyone who uses it.

That has a downside: whoever clears the browser storage or switches to another computer loses the designs. **So back up important work into a file.**

## Folders for your designs

With dozens of designs a single list is not enough. On the start page, {{ui:shared.newFolder}} makes a folder for the designs of this browser; a click on the folder opens it. Folders can hold folders.

- **Into a folder:** drag a design onto the folder, or choose {{ui:shared.moveTo}} in the design's menu, which lists every folder. A new design, and a file you open or import, made while a folder is open lands in that folder.
- **Out again:** the first tile in a folder, `..`, and the line under the tabs lead back; you can drop a design on them too. A folder dragged onto another folder goes inside it.
- **Rename and delete** are in the folder's menu. Deleting a folder deletes no design: what was in it moves one level up.
- **Search** looks through every folder; a design that is found shows its folder, and a click on it opens the folder.

{{ui:dashboard.backupAll}} keeps the folders: the designs sit in the backup file in their folders, and restoring the backup puts them back there. The folders of this browser are separate from the folders on a server. The card pictures go into the file too, so they are back as soon as you restore.

## Backing up and passing on

On the start page every design has a menu with the options to rename, duplicate and delete. The row beside the tabs has the same buttons on every tab. To delete several designs at once, click {{ui:dashboard.select}}: a click on a card chooses it (a tick shows what is chosen), {{ui:dashboard.selectAll}} chooses every design in the list, and {{ui:common.delete}} asks once for all of them. {{ui:dashboard.selectDone}} or [[Esc]] leaves the selection. With {{ui:dashboard.backupAll}} you pack all designs of the open tab into one single ZIP file. {{ui:dashboard.restoreBackup}}, beside it (it is there on a new computer with no designs, too), brings them back, also in another browser or on another computer; {{ui:dashboard.importGeometry}} takes the same file. The {{ui:myShapes.title}} travel in the same file, in the folder `Custom shapes`, see [Shapes](chapter:shapes). If you restore a backup into a browser that already has some of these designs, those are not added a second time; the notice says how many were already there. A design that cannot be read is left out, and the notice names it. If the page reloads in the middle of a backup, usually because a very large design took all the memory the browser allows, the start page says afterwards at which design it stopped: save that one on its own as a file (see below) or simplify its largest meshes, then back up again. Above the designs of this browser, a short line reminds you that they are kept nowhere else.

Only some designs: after {{ui:dashboard.select}}, {{ui:dashboard.backupSelected}} packs just the chosen designs, in their folders, into one ZIP file, and {{ui:dashboard.backupSelected}} in a folder's menu packs that folder with every design and folder in it. Neither takes the custom shapes along, and {{ui:dashboard.restoreBackup}} brings both back like a full backup. This is for the designs of this browser.

You back up a single design in the editor: {{ui:editor.export}}, choose the format **LYL** and click {{ui:export.saveProject}}. The LYL file is layerling's own design format and contains everything: shapes, groups, sketches, CAD data, imported sources and the history, meaning the undo steps. Under {{ui:export.historyTitle}} you choose how many of the last steps travel along; it starts at what the settings (the cogwheel in the ribbon) keep under {{ui:workspace.history}}. The last stop, {{ui:export.historyNone}}, saves the design with its current state only - the way to share a file without its undo steps. The export is a copy under the {{ui:export.fileName}} you give it; the design in your browser keeps its history. Older `.skf` files from earlier versions can still be opened; they are then saved as `.lyl`.

**Saving into your own folder (Chrome and Edge).** There the button opens your system's save dialog, so you pick the folder and the name yourself, and an existing file can be replaced. Afterwards [[Ctrl]]+[[S]] saves the design into that same file again, without a dialog. A design opened from a `.lyl` file with {{ui:dashboard.importGeometry}} or the open button of the export window saves back into that file, too. The browser may ask once for permission to change the file. After the page is reloaded the design forgets its file, and the next [[Ctrl]]+[[S]] asks for it again; the dialog starts in the folder you used last. Firefox and Safari do not allow a page to write into files like this. There the file is downloaded to the Downloads folder as before, and [[Ctrl]]+[[S]] downloads it again; Firefox can be set to ask for the folder each time under Settings, General, Downloads. If you give the file a different name there, the design keeps its own name, since a version or a date in the file name is often meant that way; the message after saving then offers {{ui:status.renameDraftToFile}}.

## Attachments

Instructions, a parts list, notes, a photo or a datasheet can stay with the design as files. {{ui:editor.attachments}} in the {{ui:editor.group.manage}} toolbar, the paperclip, opens the list; a small dot on the paperclip shows that the design has some.

- **{{ui:attachments.upload}}:** Choose one or more files: `.md` (Markdown) or `.txt` as plain text (UTF-8), `.png`, `.jpg`, `.jpeg` or `.webp` pictures, or `.pdf` documents. A file is checked by its content, so a file that is not what its name says is refused, and other types, `.svg` among them, cannot be attached. A text file can be at most 2 MB, a picture 16 MB and a PDF 32 MB; a design holds up to 32 files and 64 MB together.
- **The list:** The arrow downloads a file as it was uploaded. The bin removes it; the row asks once more first, and a removed file cannot be brought back with undo, because attachments are not part of the undo history.
- **Reading a file:** The eye on the row of a `.md` or `.txt` file opens it in a window to read, without downloading it. Markdown is shown formatted, with headings, lists, tick boxes, tables and code; a text file is shown exactly as it is written. Only links to web pages and e-mail addresses work, and they open in a new tab. Pictures named in the file are not loaded: their description stands in their place. Escape, the cross or a click beside the window closes it. Reading works in the History view too.
- **Looking at a picture:** The eye on the row of a picture opens it in the same window, shrunk to fit when it is large. A PDF has no eye: download it and open it in the program you read PDF files with.
- **A name that is already there:** layerling asks what to do. {{ui:attachments.replace}} puts the new content into the file of that name, which keeps its place in the list. {{ui:common.rename}} adds the new file under another name and suggests the first free one, such as `notes 2.md`. The cross leaves the new file out. Upper and lower case count the same, and the same file uploaded again changes nothing.

Attachments are saved with the design like everything else: in the browser, in a LYL file, in a backup and in a design on a server, which they reach as soon as one is added or removed. They do not come along with {{ui:import.insertProject}} or with a custom shape, and a bug report does not contain them. A design with attachments is saved as a newer kind of LYL file: an older layerling says that it cannot open it instead of dropping the files. A design without attachments is saved exactly as before.

## Exporting

Click {{ui:editor.export}} or press [[Ctrl]]+[[E]].

If the window covers something, drag it by its title bar to another spot; the Import and Attachments windows move the same way. A double click on the title bar puts it back.

![The export window with the formats STL, 3MF, OBJ, STEP, SVG, PNG, LYL and 2D.](shot:export-panel)

At the top is the file name, below it you choose the format. With something selected, only the selection is exported, otherwise the whole design. If the selection leaves out visible parts, a note in the window says so plainly, and {{ui:export.selectAll}} selects everything visible in one click. Once the file is written, the window closes by itself; if the export fails, it stays open with the message.

| Format | For | What to know |
| --- | --- | --- |
| **STL** | slicer and 3D printing | A triangle mesh. The simplest and most widespread format. An STL has no parts: bodies that overlap are joined into one mesh. To keep them as separate parts, export 3MF. In Chrome and Edge the first STL export asks where to save, and later STL exports of the design write into that file, until you type another name in the file name field or press {{ui:export.stlSaveAs}}. |
| **3MF** | slicer with colours | Every body stays a part of its own with name and colour. Overlapping bodies are only joined when they share a colour; where a shape sits inside one of another colour, say a logo in a plate, the one built first leaves room for the later one. Suited to PrusaSlicer, Bambu Studio, OrcaSlicer and Cura. Bambu Studio and OrcaSlicer ask on opening how to map the colours onto your filaments, and call the file "not from Bambu" - the message is harmless. |
| **OBJ** | modelling and exchange | A widely supported mesh format. Colours are stored as vertex colours in the same file, with no extra `.mtl`. Bambu Studio and OrcaSlicer read them and ask, as with 3MF, how to map them onto your filaments; other programs see only the shape. As with 3MF, overlapping bodies are only joined when they share a colour. |
| **STEP** | a full CAD program | Keeps boxes, cylinders, spheres and cones as exact geometry, and so shapes made from an outline (star, heart, ellipse, tube, half sphere, round roof, rounded box, dovetail, the bores and more), the bent tube, the wedge, the pyramid, the paraboloid, threads, springs and gears, plus fillets and chamfers. The first STEP export in a session loads the CAD kernel (about 22 MB) once. |
| **SVG** | laser cutter and plotter | A clean top view in millimetres, including holes and curved outlines. Under {{ui:export.svg.view}}, {{ui:export.svg.viewFootprint}} writes only the outlines where the objects stand on the workplane. {{ui:export.svg.viewEdges}} writes the edges you see from above as lines, each body in its colour; see below. |
| **DXF** | laser cutting shop | The same top view ({{ui:export.svg.viewSilhouette}} or {{ui:export.svg.viewFootprint}}) as one outline of lines, true arcs and circles - no polylines, splines or curves made of short straight pieces - on layer 0 in white, DXF 2000 in millimetres, not mirrored. Bodies that touch become one outline, so no line is cut twice. Shops ask for one part per file: select the part before exporting. Not yet tried on a laser cutter: feedback is welcome. |
| **PNG** | forum posts, print sites, questions | A picture of the view as it is, at twice the resolution and without handles, selection frames and dimensions. {{ui:export.png.plate}} and {{ui:export.png.transparent}} are chosen in the window. Turn and zoom first until the picture is right; the selection does not matter here. |
| **LYL** | layerling itself | The editable design with everything that belongs to it. |
| **2D** | workshop, lathe and mill, documentation | A drawing at 1:1 as PDF or SVG: front, top and right-side views on an ISO sheet. See below. |

**Bridges for parts that would fall out (DXF and SVG).** When a plate with text is cut by a laser or a plotter, the middle of letters like o, a and b falls out. Tick {{ui:export.bridges}} in the export window of the DXF, or of the SVG with the top view, and small bridges hold such parts to the material round them, as on a stencil: {{ui:export.bridgeWidth}} (0.5 to 3 mm) and {{ui:export.bridgeCount}} (1 to 4) are set beside it. A bridge never touches another outline or another bridge and never leaves a gap too narrow to cut; parts that would only hold each other are tied to the plate too. If a part gets no bridge at the chosen width, the message after the export says how many. Nothing changes unless the box is ticked.

**STL into your own folder (Chrome and Edge).** There the first STL export of a design opens your system's save dialog, so you pick the folder and the name yourself and can replace an existing file. After that every STL export of the design writes into that same file without a dialog; the export window shows which file, and **Save as…** next to the export button picks another. The dialog remembers its own folder, apart from the one for designs, so the slicer files can stay with the slicer. After the page is reloaded the design forgets its STL file and the next export asks again. Firefox and Safari download the file as before. If you would rather have every STL as a plain download, so that the browser numbers a name it has already used (`name (1).stl`, `name (2).stl`) as Tinkercad does, switch on {{ui:workspace.stlAsDownload}} in the settings under {{ui:workspace.appearance}}.

A hole you have not grouped is taken out of every body it reaches when you export, as the view shows it. So there is no need to group before each export. With a selection, only the selected holes count. A hole cannot be exported on its own; layerling points that out.

STEP only carries exact CAD bodies. What cannot be written exactly, such as a mesh imported as STL, is left out. The message after the export names those bodies and says why. For the printer, use STL or 3MF, which carry everything.

### SVG for a laser or plotter

With {{ui:export.svg.viewEdges}} under {{ui:export.svg.view}}, the SVG shows the design as you see it from above, like the top view of a drawing: every edge you can see is a line, and edges hidden by other parts are left out. Each line has the colour of its body, so a laser or plotter program that sorts by colour puts each colour on a layer of its own. Whether a layer is cut, scored or engraved, you choose there.

Every area a colour shows has a closed outline, and where two bodies meet, both get the line. The areas are filled even-odd, so filling a colour to engrave it leaves its holes and the places of other bodies free. A part reaching through another gets the line where it comes out. The SVG is at 1:1 in millimetres, with the front of the design at the bottom of the page, in the same place as the silhouette. A design with too many edges for this view, such as a plate with hundreds of holes, gets its filled silhouette instead, and the message after the export says so.

### A drawing for the workshop

Choose the format **2D** (hover over it and it says Drawing) and, below the file name, PDF or SVG. With something selected, only the selection is drawn, otherwise the whole visible design; holes you have not grouped still cut the parts they reach.

layerling draws the front, top and right-side views in first-angle layout (the right side to the left of the front view, the top view below it) on the smallest ISO sheet that fits, from A4 to A0, or a larger one if the part needs it. It is always at 1:1. Each view carries its overall width and height, and edges you cannot see are dashed. Round bores that run parallel to a view direction get a centre cross and a label (F1, T1, R1), and a table at the bottom lists their diameter and position, measured from the lower-left corner of the view. The title block in the lower-right corner holds the name, scale, units, date and sheet number. The words on the sheet follow the interface language.

Print at 100 % or "actual size", or the lengths will not match. What the drawing does not do: threads, depths, tolerances and bores at an angle are not dimensioned, and the sizes come from the model as a mesh, so they are nominal. A very detailed part (over 100,000 triangles) or more than 200 bores is refused with a message; choose fewer objects then.

The projection is based on the drawing work of Cadverix-3D by WC3D.

### How much filament does it take?

For STL, 3MF, OBJ and STEP the {{ui:export.estimateTitle}} box shows the volume, weight and length of 1.75 mm filament of what is exported. It counts like the file: visible bodies only, holes taken off, overlaps only once. On the right you pick the filament - PLA, PETG, ABS, ASA, TPU or PA (nylon) - and the weight follows its density. The volume is the body's own. Weight and filament are a rough estimate for a print with walls and infill: you set the {{ui:export.estimateInfillLabel}} (15 % to begin with) and the {{ui:export.estimateWallsLabel}} (2) under the heading, and the box says what it counted and what the same part would weigh solid. Your slicer's own settings decide the real number, so take it as a guide: good for comparing designs and for whether the spool will last. At 100 % infill the box counts the part as solid, the upper bound. The box works out its numbers when you press {{ui:export.estimateCalculate}}, so the export window opens at once even for a finely traced model.

## Importing

With {{ui:editor.import}} or [[Ctrl]]+[[I]] you bring foreign files into the design.

![The import window: open or insert designs and drop geometry.](shot:import-panel)

- **{{ui:import.openProject}}:** A layerling design (`.lyl`, or an older `.skf`) comes back as a new design.
- **{{ui:import.insertProject}}:** The bodies of a layerling design are added to the open one. Handy for basic shapes you need again and again: build them once, save them and bring them in every time. Drop one or more `.lyl` files on the drop zone below and they are inserted the same way. Its [notes](chapter:measuring-and-notes) come along, closed and numbered on after the ones already in the design, and so do its reference points.
- **DXF:** A DXF, as a laser cutting shop or a supplier sends a part outline, comes in as parts to work on: every closed outline a body 4 mm high and every hole in it a hole of its own beside it (a round one a cylinder), so a hole is moved and sized in the 3D editor like any other; select them all to move the part. In millimetres (a file in inches is converted, one without a unit is read as millimetres), arcs and circles kept as true arcs. Lines, arcs, circles, ellipses, polylines, splines and blocks are read; text, dimensions and hatches are left out, and outlines that do not close too - the message says how many. Set the thickness in the properties.
- **Add geometry:** Drop STL, OBJ, 3MF, STEP, SVG, PNG or JPG files in the window or click to choose a file. Imported meshes can be turned, moved, cut with holes and built upon. A STEP file with several solids, an assembly from another CAD program, comes in as one body each under the name the file gives it, in its place to the others and in the colour the file gives it; several bodies under one entry of the file, the screws of a part say, become a part each. Its groups are not taken over yet. An SVG comes in as a sketch body, one from a tracer such as picsvg.com or Inkscape's "Trace Bitmap" as well: its outlines become the lines and curves of a sketch, 4 mm high and reading from above as in the drawing. In the properties you set its {{ui:prop.sketchFill}}, an area or a stroke outside, inside or centred, and {{ui:prop.sketchSilhouette}} leaves the holes out, see [Sketches](chapter:sketches), "Fill and silhouette". You change the points themselves in sketch mode. If it should come in at a size of your own, type the width in the import window under **SVG and picture: width in mm** first, as in Tinkercad: the drawing is scaled to it, height and depth with it, and the field is empty again after that one import; left empty, an SVG comes in at its own size and a picture 50 mm wide. Only a very intricate SVG with more than 2500 lines and curves comes in as a fixed mesh. A PNG or JPG picture is traced into an outline and comes in the same way, as a sketch body 50 mm wide that you can resize afterwards: the part of the picture that is not its background, the background being the part that takes up more of the picture's edge. An SVG that holds nothing but one picture is traced the same way. A shape that cannot be built into a solid, such as an outline that crosses itself or touches itself at a point, is left out, and after the import layerling says how many there were. Then it helps to join overlapping pieces in the drawing program, close the outlines and save the file again. Drawings made on one page, such as the layers of one document exported as separate files, line up again when you switch on {{ui:import.keepSvgPage}} in the import window before you import them: each keeps its place on the page, where otherwise each is centred on itself. An SVG drawn in several colours comes in as one body per colour as well, each in its colour and in its place; with more than 12 colours, as a traced picture has, it stays one body. A coloured OBJ or 3MF comes in as one body per colour, each in its place. In an OBJ the colours sit either in the file itself, as in an OBJ from layerling, or in an `.mtl` beside it. Select that one too, or import the whole ZIP the way Tinkercad hands out its OBJ. A 3MF carries its colours itself, and in a project from Bambu Studio, OrcaSlicer or PrusaSlicer each part takes the colour of its filament. A 3MF with several objects, such as a project with one object per plate, comes in as one body per object; modifiers, negative volumes and support blockers from the slicer are left out. Colour painted onto faces in the slicer is not read.
- **From Tinkercad:** An STL or OBJ export from Tinkercad comes in as geometry like any other mesh, and an OBJ keeps the colours. The real shapes come across with a free tool from the community: [Export to layerling](https://taylormadearmy.github.io/tinkercad-layerling-importer/) by taylormadearmy, a bookmark that converts a Tinkercad design in your browser into a `.lyl` file, which you open here with {{ui:import.openProject}}. It is not part of layerling and we have not tested it ourselves yet; its author tested it on Windows with Chrome.

A design saved with a **newer layerling** may hold things your version does not know yet, such as a new shape, a new setting or fonts of one's own. If layerling cannot open it for that reason, the message names both versions. If it opens, the notice says that newer things may look different here. Either way, reloading the page helps: layerling.com always serves the newest version. The installed app picks it up the next time it starts; on your own server you install the update.

Template pictures are added in sketch mode, see [Sketches](chapter:sketches).

## Simplifying an imported mesh

A scanned or sculpted mesh often has far more triangles than its shape needs, and every one of them is carried along while you move, cut and save. {{ui:simplify.title}} in the Modify group (or in the right-click menu of the body) shows the mesh as it is next to what a chosen share of its triangles would leave of it; both views turn and zoom together with the mouse buttons of the workplane. Set how much to keep as a percentage or a number of triangles, and {{ui:simplify.apply}} takes the lighter mesh. The result is a plain mesh: for the result of a cut or merge, {{ui:group.edit}} and its original parts are given up.

Cutting, merging and intersecting an imported mesh is calculated in your browser, so the workspace settings limit how many triangles such a mesh may have ({{ui:workspace.booleanTriangleLimit}}). A mesh above the limit is not processed, and the message names its triangle count; simplify the mesh first, or raise the limit if your computer can take it.

## Reporting a bug

If layerling does something unexpected, save a {{ui:editor.bugReport}}: the link sits in the footer at the bottom, next to the forum. It is a ZIP file, because GitHub and many forums refuse a bare .lyl: inside are your design as a .lyl and a short text file with the version, browser, screen size, the last messages and any errors. The start page opens the ZIP like a backup, or you unpack it and open the .lyl. Nothing personal is in it. Attach the file to your post in the forum or on GitHub, so the problem can be followed with exactly your design.

If layerling stops with an error, a window with the error message shows instead of a blank page. From it you can save the state of the design last stored in the browser as a .lyl file, go back to the overview, or start a new design. The error message from the window and the saved file help when you report it.

## Shared designs on a server

When layerling runs on your own computer or web server, it can offer a shared folder in which all users keep designs. The start page then holds the designs in two tabs, {{ui:shared.trailRoot}} for the shared folder and one for this browser, each with the number of designs in it; the one with more designs comes first and is open. You create folders there, move designs by dragging and search across the whole folder. A design that lives there saves itself back to it. A design from this browser goes onto the server by dragging its card onto the {{ui:shared.trailRoot}} tab, or with {{ui:dashboard.sendToServer}} in the card's menu. While the {{ui:shared.trailRoot}} tab is open, {{ui:dashboard.createDesign}} and {{ui:dashboard.restoreBackup}} put the design into the server folder you have open, and {{ui:dashboard.backupAll}} packs every design of the server, in its folders, and its custom shapes into one ZIP file. The start page shows a design by its file name, so renaming a design, on its card or at the top of the editor, renames the file on the server too. Deleting a design or a folder removes it for good, together with its working copy in this browser. Custom shapes kept on the server sit in its folder `Custom shapes`, see [Shapes](chapter:shapes).

Two things make that quicker: {{ui:dashboard.sendAllToServer}} on the start page puts every design of this browser on the server in one go, and ticking {{ui:dashboard.newOnServer}} makes every new design start in the server folder, so it is saved there from the first change on. With the tick, everything else that makes a design starts there too: opening or importing a file, {{ui:dashboard.restoreBackup}} (with the backup's folders), duplicating and taking a state from the history, each into the server folder you had open; {{ui:shared.newFolder}} on the start page then makes a folder on the server. A design made in the first moments waits until the server has answered. When new designs must always start on the server and this browser holds none of its own, the start page shows only the server's designs. The tick is kept in this browser. A design that cannot go - its name is taken on the server, say - stays in the browser, and the message says how many.

The other export formats (STL, 3MF, OBJ, STEP, SVG, PNG and the drawing) can go into the same folder: in the export window, {{ui:export.saveToShared}} writes the file next to your design, or into the folder you have open on the start page for a design that is not on the server. A program that shares the folder, such as a slicer in Docker, can open it from there. The file does not appear in the list of designs. If a file of that name is already there, the message says so, and pressing the button again replaces it.

That is not simultaneous editing: whoever opens a file works on a copy of their own. If somebody else has changed the file in the meantime, layerling refuses to overwrite it.

On layerling.com this function is not switched on. How to set it up on your own server is described in the [README on GitHub](https://github.com/henmedia/layerling/blob/main/README.md).
